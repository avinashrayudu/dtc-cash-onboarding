dtc-cash-onboarding

Every brand sends different files. This tool maps a brand's Shopify, Amazon, Faire, bank, card and chart-of-accounts exports into one cash ledger, and accepts the result only when independent records of the same money agree. What it cannot prove, it sends to a person instead of guessing.

Built by Avinash Rayudu. 13 synthetic brands: 7 to train, 3 to develop against, 3 written after the code was frozen.

How it works

1. ReadCSV, TSV, semicolon, xlsx; finds the real header under summary lines
2. Recognize and mapsource type and columns from header and value evidence; memory first
3. Standard tablessigns, dates, decimal commas, line-item totals, duplicates across uploads
4. Tie-outs (the gate)payouts, settlements, card payments and balances must agree with the bank
5. Label each lineby proof (tie-out), then memory, then the model; abstains below threshold
6. Decideaccepted, open review items, or blocked with the failing check named

The model never decides alone. A deposit that equals a Shopify payout to the cent within three days is labeled by proof. The model (2606 training lines, logistic regression on character and word n-grams) only labels what is left, and only above a threshold chosen for 99% precision on brands it did not train on.

What the holdout found

The holdout brands were written after the code and model were frozen (hashes in evals/FREEZE.json). Their blind results are kept unchanged in evals/results/holdout_v1_frozen/. They exposed four real problems:

  • A hole in the gate. Two brands ended accepted although their bank data never tied out: every bank check was "not applicable", and the gate read that as a pass. Now an upload with no readable bank rows, or a file whose mapping drops rows, is blocked.
  • Dates written 01-07-2026 (day-month-year with dashes) did not parse, so a correct mapping still read no rows.
  • Unsigned amounts with a separate DR/CR column. The file had no negative numbers, so it was taken for a card statement and accepted under the wrong type.
  • Shopify payouts exported one row per transaction. The gate correctly refused this brand; the pipeline now rolls transactions up to payouts. Its PayPal deposits, which have no export, are flagged and need a person to confirm them.

The fixes were made after seeing the holdout, so the second set of numbers is not a blind test.

Limits

  • All data is synthetic, and I wrote both the generator and the pipeline. Accuracy on quirks I designed overstates accuracy on real exports; the holdout exists to show how much.
  • The simulated reviewer answers from ground truth. Review counts measure how much a person is asked, not how long it takes.
  • Supported sources: Shopify orders, Shopify sales reports, Shopify payouts, Amazon settlement and date-range reports, Faire payouts, bank exports, card exports, chart of accounts. PayPal, Stripe and 3PL invoices are not imported yet.
